# 桌面收件箱低保真原型

## 要回答的问题

桌面收件箱的核心操作，怎样在一个界面里让用户看懂建议、修改选择并放心执行？

## 原型性质

这是一次性 UI 验证原型，不是正式产品代码。所有数据均为模拟数据，点击“执行整理”不会访问或移动真实文件，页面刷新后状态重置。

## 三种方案

### A — 审核工作台

- 中央密集列表展示待整理项目。
- 右侧固定显示计划摘要和风险。
- 适合文件较多、希望批量审核的用户。

验证点：信息是否过密；右侧摘要是否足以建立执行信心。

### B — 分类看板

- 按“文档、图片、安装包、待决定”分栏。
- 分类结果更直观，突出拖拽和项目归属感。
- 适合视觉型用户和中等规模桌面。

验证点：大量文件时是否难以浏览；用户是否误以为拖动已经移动真实文件。

### C — 安心向导

- 一次聚焦一个决策，逐步确认高风险项目。
- 强化安全说明、目标位置和撤销承诺。
- 适合首次用户或对自动整理缺乏信任的用户。

验证点：日常高频使用是否显得过慢。

## 使用方法

打开 `prototypes/desktop-inbox-prototype.html`，使用底部左右按钮或键盘方向键切换。URL 参数可以直接分享具体方案：

- `?variant=A`
- `?variant=B`
- `?variant=C`

## 建议评审问题

1. 第一眼是否知道哪些文件将被处理？
2. 是否知道文件为什么被分到某个位置？
3. 冲突和风险是否足够明显？
4. 点击执行前是否感到放心？
5. 更偏好批量审核、空间分类，还是逐步向导？
