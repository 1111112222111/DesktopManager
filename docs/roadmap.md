## 阶段 0：原型决策

目标：确认首页的信息层级与主要操作方式。

1. 查看三套原型。
2. 选择一个主方向，允许组合其他方案的局部元素。
3. 记录选择原因：是否容易发现待整理项、是否敢点击执行、冲突是否显眼。
4. 将获胜方案重写成正式界面，原型继续保持可抛弃状态。

产出：明确的首页布局决策和首版交互说明。

## 阶段 1：环境与工程骨架

已完成：安装 .NET 10 SDK，并建立 WPF、核心、基础设施和测试项目。

建议项目结构：

```text
src/
  DesktopManager.App/             WPF UI 与应用生命周期
  DesktopManager.Core/            领域模型、规则与整理计划
  DesktopManager.Windows/         Windows Shell 和文件系统实现
  DesktopManager.Persistence/     SQLite 操作日志与设置
tests/
  DesktopManager.Core.Tests/
  DesktopManager.IntegrationTests/
```

完成标准：一条命令能够还原、编译并执行测试。

## 阶段 2：第一个纵向切片

目标：只针对测试目录跑通安全闭环，不碰真实桌面。

### Slice 1：扩展名规则整理

1. 扫描测试目录中的文件。
2. 使用内置扩展名规则生成整理计划。
3. 在界面或命令行展示原路径与目标路径。
4. 用户点击立即执行，预检通过后移动文件。
5. SQLite 持久化日志记录每个操作项。
6. 重启程序后撤销移动。

完成标准：

- 计划生成阶段不会修改文件。
- 同名文件不会被覆盖。
- 其中一个文件失败时，其他结果仍被准确记录。
- 撤销后文件返回原位置。
- 自动化测试始终使用临时目录。
